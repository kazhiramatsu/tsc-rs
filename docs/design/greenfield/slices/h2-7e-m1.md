# H2.7e m-1: non-bundle declaration-map recording

This packet connects the declaration printer to the existing source-map
recorder and constructs declaration map/text artifacts. Whole-Program
activation, bundle composition, sink failures and the H2.7e corpus closure
remain subsequent integration work. `declarationMap` remains a typed runtime
refusal until that integration.

## Source authority

TypeScript 6.0.3 at `050880ce59e30b356b686bd3144efe24f875ebc8` owns the
observations. `emitDeclarationFileOrBundle` (`_tsc.js:116640-116715`) sets the
printer's map flag from `declarationMap`, enables declaration brace omission,
and passes `sourceMap`, `sourceRoot` and `mapRoot` to the shared output worker.
Neither inline option enters that map-options projection. Consequently
`inlineSourceMap` still produces an external declaration map and
`inlineSources` does not append `sourcesContent` to it.

The existing `printSourceFileOrBundle` map path (`_tsc.js:116744-116804`)
registers original source files, records the source map, appends its URL,
writes the map first, and writes the declaration with separate BOM and
metadata. The URL metadata offset is the generated UTF-16 writer position.
The emitted-file list names the declaration before the map; callback order
is a separate observation.

The pinned native reference
`1f70213d4922b434345f639b441681e470c7cfc1`,
`tsc/internal/compiler/emitter.go:221-292`, retains the same inline-option
omission and brace policy. Its additional content-mapped source `SpanMap`
callback is a native-version feature, outside this 6.0.3 packet. Native
force-emit skip differences are likewise not adopted here. This packet
reviews that source; it does not claim a new native reference test run. Native
`transformers/declarations/transform.go:1074,1129` uses update faces for
constructors and methods, unlike the 6.0.3 create faces. This packet retains
the 6.0.3 ranges required by the complete recorded maps; it does not claim
native map parity. Native `checker/nodebuilderimpl.go:1758` also clones
parameter names, and `printer/printer.go:5801,5844` records comment endpoints
through its source-position conversion.

## Independent seam

`Printer::print_declaration_with_recording` preserves the existing declaration
global-name handler and calls the same `print_source_file` recorder used for
JavaScript. Existing `print_declaration` callers continue to pass no recorder.
The declaration transformer supplies original/source ranges; map segments
are generated from those ranges, rather than inferred from matching output
text.

`declaration_map_recording_inputs_for` applies the declaration option
projection before using the existing source-root, map-root and source-file
path workers. `finish_declaration_map` creates the complete map and
URL-bearing declaration artifacts and the `SourceMapObservation`. The
executor remains responsible for whether a unit may print, callback
invocation, write failures and result/list ordering.

## Focused observations

`scripts/observe-declaration-maps.mjs` records 24 complete command observations
twice with a hermetic virtual project and physical fallback limited to pinned
standard libraries. The fixture contains all write bytes and materialized
bytes, BOM, source association, callback metadata, command diagnostics,
status writes, exit, emitted-file list and source-map result. No Rust output
is used to create expectations.

The controls cover variable inference and annotations; generic functions;
interfaces, aliases and tuple/array types; classes and parameter properties;
enums; namespaces; JSDoc and non-ASCII/astral source text; stripping; empty
and erased sources; multiple independent files; absolute and relative
`declarationDir`; relative/absolute/URL map roots and source roots; inline
flags; BOM/newline/comment options; URI escaping; and JavaScript/JSDoc.
The `declarationMaps.ts` control retains its vendored source hash and is
explicitly a declaration-only derived control, separate from the original
corpus row. Source-root controls preserve TS5051 and their partial output.

The Rust focused test invokes the declaration transform and the production
printer/map construction seam twice per control. It compares exact map/text
artifacts, metadata offsets, materialized bytes and map/source association.
It does not substitute those printer-level comparisons for the recorded
Whole-Program command, callback fault or full corpus acceptance boundaries.

## Mapping producer corrections

The first direct comparison matched 20 controls and exposed four differences
from three producer causes. Both ordinary `.d.ts` content and the complete map
are compared, so these mapping differences cannot hide behind text parity.

- Constructor and method declaration visitors used `create...Declaration` and
  then copied the input text range through a local update helper. Upstream's
  create faces retain synthesized ranges and the cleanup only preserves JSDoc
  and original identity. The two visitor arms now follow that order; the local
  helper had no other callers and is removed.
- Comment mapping treated the UTF-16 offset returned by `compute_line_starts`
  as a byte slice offset. The calculation now subtracts offsets in UTF-16.
  This affects the shared source-comment recorder after Unicode on an earlier
  line; the two non-ASCII controls expose the same cause.
- NodeBuilder parameter names use `factory.cloneNode` without `setTextRange`.
  The parameter-name faces now use a dedicated synthesized clone while
  preserving parse provenance and cross-source remapping. Other parse-clone
  users retain their prior range policy.
