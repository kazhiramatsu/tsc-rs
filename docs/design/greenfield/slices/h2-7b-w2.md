## 3. Mechanisms ported in this wave (from the lanes' mechanism notes, written before code; every port is upstream behaviour with no fixture inference)

**W2-B (emitter declaration transformer, printer, option diagnostics) — 36 rows**
1. **B1 — the exclamation token never reaches the declaration file** (6 rows). Upstream `visitDeclarationSubtree`, PropertyDeclaration arm (`_tsc.js:115096-115109`) rebuilds the property with `input.questionToken` only; Rust `crates/emitter/src/declarations/subtree.rs::update_property` passed `question_token.or(exclamation_token)`. The sibling arms (PropertySignature `:115110-115125`, `ensureParameter` `:114642-114666`, the accessor arms `:115060-115095` / `:114764-114792`) were audited and already match.
2. **B4 — the merged-options removed/deprecated pass for emitting config-backed programs** (20 rows exact + 2 strict subsets). Upstream `verifyCompilerOptions` → `verifyDeprecatedCompilerOptions` (`_tsc.js:125087-125250`) checks the merged effective options; `createDiagnosticForOption` (`:125368-125386`) falls back from option syntax to the `compilerOptions` property to a file-less diagnostic. Rust `crates/compiler/src/lib.rs::programmatic_option_diagnostics` returned nothing whenever a config file owned the option diagnostics, and the config pass (`crates/program/src/config.rs::deprecation_option_diagnostics`) only sees config-text options, so the project runner's overlays (`module` variants, `moduleResolution=classic`) were never checked. The port runs the existing merged removed/deprecated blocks (and `ignoreDeprecations`) for config-backed programs, skipping every option that has config syntax (`compiler_option_name_locations` non-empty — already reported by the config pass), so no row doubles; the validation/path diagnostics stay config-owned. Boundary: the explicit no-emit project adapter (`load_project_no_emit`: `no_emit = true` + external config) keeps `ConfigRootPlan` ownership, as its contract filters config rows by design; the emitting project route runs the pass. Adjacent-band effect: six H2.5h project rows became exact (E2a).
3. **B2 — the JSDoc of a non-identifier `export default` moves to the synthesized `_default` statement** (1 row). Upstream `visitDeclarationStatements`, ExportAssignment arm (`_tsc.js:115287-115308`): `preserveJsDoc(statement, input)` then `removeAllComments(input)` (`:25311-25317`: `NoComments` + cleared synthesized comment lists). Rust `declarations/statements.rs` created both nodes without either; the port reuses `subtree.rs::preserve_js_doc` and adds the general `remove_all_comments` emit-metadata primitive (`metadata.rs` / `factory.rs`).
4. **B3 — declaration-printer comment ownership and filtering** (9 rows exact + 1 strict subset), three ports in `crates/emitter/src/printer.rs`: (a) upstream `emitNodeListItems` (`_tsc.js:120068-120145`) emits comments after a parsed comma as a list-boundary phase whose emitted-comment state the next node's comment phase observes; Rust's parameter-list specialization discarded that phase's `CommentResume`, so the next parameter re-emitted the inline block comment — the general `delimited_comment_resume_for_node` hand-off now applies to parameter lists; (b) `shouldWriteComment` (`:121145-121150`) under declaration printing keeps only JSDoc-like and pinned comments, including the list-end leading phases (`:120139-120145`) — Rust's list-element and final-delimited-list helpers passed a literal `false` instead of `only_print_js_doc_style`; (c) `emitVariableDeclaration` emits `node.name` through the ordinary node pipeline under the declaration containers (`:117897-117902`, `:121007-121030`) — Rust emitted the name directly and skipped its source-leading phase, dropping JSDoc owned by a retained binding-element name.

## 4. The manifest re-mint and its review

The first w2 sweep (write mode to the canonical path, on the merged train) re-mints `ratchets/h2-7b-known-divergences.v1.json`; the review is componentwise against the w1 manifest (the m-2 §6 rule, no registered exception): every surviving row byte-identical or a STRICT SUBSET of its w1 vector; deletions are the closed rows; any added or replaced element, new row, ANY owner change, boolean `false → true`, or numeric increase is rejected (`target/session-notes/7b/lanes/w2/audit.js` implements the full rule for the lane batteries AND the E2 review, mirrored on the runner's vocabulary (`h2_2c_acceptance.rs` `vectorize_writes` / `vectorize_diagnostic_rows` / `vectorize_successful_observation` / `vectorize_refusal`): `writes_diverging` = write indices with any `write:N:*` or `write_N_data_diagnostic:*` element; `diagnostics_diverging` = any `reported_diagnostic` element; `emit_result_diverging` = any `emit_result` / `emit_diagnostic` / `emitted_files` / `source_maps` / `status_writes` / `exit_code` element; a refusal row = exactly one element `refusal:0:variant=` + sha256 of the compact JSON `{"kind":"UnsupportedCompilerOption","option":<refused_option>}` (the runner's `mismatch_value_sha256`), `emit_refused` true; unchanged rows must be deep-equal as whole rows (vector order included); vectors must be sorted and unique; the fingerprint is re-derived as sha256 of the sorted vector JSON; survivors may only lose elements (none added or replaced) with monotone coarse facets (no `false → true`, no numeric increase) and unchanged refusal fields; new ids, duplicate ids on either side and owner changes are rejected; the script refuses if any canonical row contradicts the derivation, i.e. if the runner's formula drifted). Adjacent-band manifests (6c/5h/6a/6b) may only shrink. TO-FILL: closed / byte-identical / strict-subset / added / new counts.
