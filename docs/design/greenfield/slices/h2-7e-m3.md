# H2.7e m-3: ordinary declarationMap with declarations disabled

Ordinary whole-Program emit now accepts `declarationMap: true` when
`declaration` is absent or false. TypeScript 6.0.3 reports TS5069, emits the
normal JavaScript and returns no declaration map. This is an option
diagnostic with output, not a successful declaration-map operation and not a
Rust request refusal. Getter and forced-map operations retain their separate
typed boundary in this packet; bundle, targeted and noEmit owners are unchanged.

The unchanged original
`typescript-6.0.3/compiler/declarationMapsWithoutDeclaration.ts#default`
input and complete observation are joined from the hash-pinned H2.7d/e
candidate input/reference artifacts. Compiler options have no declaration
floor. Program source order, ordered libraries, full reported/emit diagnostics,
all JavaScript callback bytes/BOM/source association/metadata, emittedFiles
and sourceMaps presence, and the refusal alias are compared twice. The
original TS5069 and 37 JavaScript bytes remain the expectation.

`observe-declaration-maps.mjs --disabled-declaration` records the original
omitted option plus an explicitly named false-option control from those same
source files. It repeats both observations and writes a separate fixture;
the original 24 and runtime-three fixtures are unchanged. The real Rust CLI
also runs the original and both controls in relocated input trees, comparing
output bytes and process/status facets against the frozen reference. Its
complete config-diagnostic stdout/stderr and exit are additionally compared
with the pinned TypeScript CLI in that same input tree. No config diagnostic
location is substituted into the original Program observation.

The first complete comparison exposed a missing Program-owned TS5069;
removing the emitter refusal alone incorrectly returned no diagnostic. The
shared option validator now reports `DeclarationMapRequiresDeclaration` in
`verifyCompilerOptions` order (`_tsc.js:124874-124876`), using the existing
Program/config diagnostic location producers. The unchanged mapRoot plus
declarationMap unit control now retains this independent declaration
prerequisite diagnostic instead of receiving a declaration option floor.

`validate_emit_options` removes only the ordinary invalid-declaration
rejection. Source-map allocation remains effective-option based, so an
ineffective declarationMap flag cannot allocate a map result or activate
JavaScript map recording. The old zero-activity refusal control now covers
`declarationMap` plus the still-refused `outFile` route; getter/forced map
refusal controls remain until their own implementation packet.

This change does not add activity/profile/adoption markers or change census
membership. The original corpus comparator can move the unchanged source row
from typed refusal to an exact observation after integration. The native
reference remains the pinned source reviewed in m-1/m-2; this packet follows
the fixed 6.0.3 option diagnostic and result semantics.

job and one test thread at background priority. All seven dedicated compiler

Program/CLI/sink comparisons and the new omitted/false declaration controls.
All seven Program option-validation unit tests pass. Clippy passes with

TypeScript observation modes all pass byte-for-byte freshness checks.
The 19 emitter output-plan contract tests also pass, including the unchanged
zero-activity boundary assertion moved to the remaining outFile owner.
Formatting and diff whitespace checks pass.
