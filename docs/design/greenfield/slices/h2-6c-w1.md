## 2. Probe fidelity (confirmed + tightened per objections 2, Q3-Q5)

- The production CLI is DISQUALIFIED as a probe: the compiler-suite
  harness pins absent `newLine` to CRLF (execution.rs:334, the
  CompilerBaselineRunner rationale) while production emission maps
  `None => LF` (execute.rs:656 — not "host default"; it does not
  query the host). Mapping coordinates are newline-width independent
  (writer.rs:200), so mapping evidence gathered via the CLI stands.
- The probe generalization must reproduce the H2.6c EXECUTION ROUTE,
  not just the artifact path: all W1 candidates run through
  `recorded-compiler-plan` with `EmitOptionFloor::MapFamily`
  (h2_2c_acceptance.rs:3637); the existing band probe instead uses
  the direct qualification loader + `SourceMap` floor and hardcodes
  case-sensitive hosting (execution.rs:165) that some recorded
  fixtures contradict. The W1 probe reuses the recorded plan +
  MapFamily route.
- Probe output per write: callback bytes AND materialized bytes,
  path, write index, BOM flag, source provenance, callback metadata —
  acceptance compares callback hashes and BOM separately
  (h2_2c_acceptance.rs:2382); materialized bytes alone hide the
  diverging facet (`emitBOM.ts` is a live two-write example).
- Selector: exact case ID or exactly-one-match required (the current
  substring `.find` silently takes the first match); setting both the
  6a and 6c selectors is an error; dump names carry write index +
  full path (basename collisions exist in multi-output cases).

## 3. Defect classes (round-1 observations CONFIRMED, causes per sol)

- **K1 — parameter-property store misses its statement-end mapping.**
  `sourceMapValidationClass.ts#target=es2015`: the oracle's final
  `,CAAQ` segment is the generated statement-end mapping (generated
  col 33 after `;` → parameter end, source col 39). Later mappings
  re-align via delta state (the draft's "every later segment
  disagrees" was wrong). CAUSE: TypeScript-visitor projects the
  parameter into a synthetic property (builtins.rs:10071);
  class-fields lowering materializes the store via
  `materialize_moved_instance_initializers` →
  `create_property_initializer_statement`, which copies its range
  from the synthetic property (class_fields.rs:1204) and never sets
  the outer trailing range. Upstream sets
  `setSourceMapRange(statement, propertyOriginalNode)` when the
  property's original is a parameter (_tsc.js:97454). FIX SHAPE: the
  materialized statement takes the original parameter as its explicit
  source-map range. Verify on BOTH the ES2015 class-fields path and
  ES5 downleveling variants before mechanical rollout (Q7).
- **K2 — namespace lowering emits unpositioned synthesized names.**
  `sourceMap-Comments.ts#target=es2015`: the oracle maps
  name-start (0,10), name-end (0,13), declaration-end (18,1) —
  `IAAU,GAAG,CAkBZ`. CAUSE (two sites):
  `create_declaration_identifier_with_original` sets original
  provenance but no text range (builtins.rs:11869) where upstream
  `getName` clones + `setTextRange` (_tsc.js:24788); and
  `namespace_parameter_name` → `create_parameter` produces an
  unpositioned IIFE parameter (builtins.rs:12871, 12146) where
  upstream sets the generated parameter name's source-map range to
  `node.name` (_tsc.js:95717). FIX SHAPE: name text ranges on
  declaration/local references + explicit source-map range on the
  IIFE parameter.
- **Shared-cause ruling (Q2, agreed):** K1 and K2 are SEPARATE
  caller-level range-propagation defects. The generic
  `set_original_node` rule is NOT touched: the printer already honors
  explicit node ranges and trailing ends (printer.rs:12485, 12517);
  making original links inherit ranges would diverge from upstream's
  deliberate identity/range separation.
- **K3 — remaining families TO-VERIFY(probe)** (jsxFactory*,
  string-literal newline, contextualTyping, decorators, …): one
  representative founds a hypothesis; CLASS MEMBERSHIP is established
  per case (frozen membership table added here before any mechanical
  implementation), each class confirmed on its target variants.
