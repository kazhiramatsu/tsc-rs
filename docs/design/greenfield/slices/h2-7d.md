# H2.7d bundle output

Status: planning, transform, and script-printer foundations, 2026-09-07, based on `fd95c196` and the
[original candidate preparation](h2-7de-candidate-preparation.md). Bundle
runtime admission remains closed. These packets change the typed
output planner and internal transform/printer ownership; they do not claim complete JavaScript/declaration bundle
emission, hosted acceptance, or H2.7d completion.

## Planning packet

The existing `EmitBundle`/`EmitRoot::Bundle` foundation already modeled one
bundle output unit, but its planner treated a targeted request as a one-file
bundle, included external modules under every module kind, resolved relative
outFile callback names to absolute paths, and retained JavaScript paths for
declaration-only requests. It also derived `.d.ts` paths by replacing any
last extension, which differs from TypeScript's supported-extension rule.

The planner now follows the pinned 6.0.3 branches:

- A nonempty outFile selects from the whole Program in source order,
  including for a targeted planning request. External modules participate
  only under AMD, System, or `emitDeclarationOnly`.
- Bundle output paths preserve the raw outFile spelling. `outDir` and
  `declarationDir` do not relocate bundle members. Declaration-only output
  has no JavaScript or JavaScript-map member.
- Declaration paths remove only the supported case-sensitive extensions,
  testing compound declaration extensions first. Ordinary and forced
  planning share the same path worker. A forced `.d.ts` path does not imply
  a declaration-map path when neither declaration nor composite is enabled.
- Forced declaration plans retain the ordinary Program's collision
  diagnostics and blocked paths. The forced projection removes JavaScript
  members while preserving the bundle root and source order.

Relative callback names remain distinct from canonical collision keys.
The existing overwrite and duplicate-output owner checks both members before
emission. No-output and empty-string outFile cases retain their absent-path
distinctions. JSON eligibility recognizes a nonempty outFile.

A planning host can supply the Program's retained module-detection fact
without borrowing checked syntax. The bundle global-script filter requires
that fact or the parsed `external_module_indicator`; a host with neither
returns `CheckedSyntaxUnavailable` instead of assuming that the source is a
global script. Non-bundle selection and bundle selection with the module
filter disabled continue to need neither fact nor syntax.

The compiler's preparation host supplies no syntax. Its common-source-
directory projection now calls the shared `sourceFileMayBeEmitted` predicate
directly, matching `getCommonSourceDirectory2`, so external modules remain
directory candidates even when outFile would omit them. This also preserves
the production option-refusal order before checked planning begins.

`plan_source_requests` already parses each non-JSON source using effective
module detection, JSX detection, extension, and implied Node format. Its
`SourceRequestPlan` now retains that exact external-module verdict. The
loader stores it on `PreparedSourceFile` and the compiler projects it onto
`EmitSource`; JSON has an explicit false verdict. This adds no parse and
does not retain an extra AST. Hand-built preparations keep an unknown
`Option<bool>` until their embedding host supplies the fact or checked
syntax becomes available.

The option, output-plan, and declaration-transform runtime
refusal boundaries remain in place. In particular, planning a target does not admit the
ordinary targeted Program API owned by H2.8d. Prepend and project-reference
inputs retain BLD1 ownership; no runtime option is dropped to bypass these
boundaries.

## Transform ownership packet

The internal `transform_nodes` driver now accepts a bundle root. It applies
each transformer to every bundle member in source order before starting the
next transformer, matching `chainBundle` (`_tsc.js:92747-92755`) and
`transformNodes` (`116052-116075`). The `allowDtsFiles` gate applies to a
standalone source root; bundle visitors retain their own member policy.
Ordinary built-ins already skip declaration files. DeclarationTransformer
overrides the bundle visitor with the existing typed refusal until its
shared references and ambient module wrappers are implemented.

Helpers are retained per source between passes and selected again during
printing. Previously one context list was sufficient for one source. Sharing
that list across a bundle would leak a previous member's helper requests
into another member's `importHelpers` rewrite and final print. The same
source ownership now also applies when an internal transform call contains
several standalone roots. Error disposal clears both pending and retained
helpers. Returning a bundle from a source-file visitor remains a typed
unsupported operation; this does not introduce a custom-transformer ABI.

`scripts/observe-bundle-transform.mjs` freezes eleven internal phase/helper
traces and four real built-in helper observations, each repeated in a fresh
transform session. The controls include empty and mixed roots, source order,
standalone and bundled declaration files with both gate values, replacement
source IDs in either pass with retained helpers, isolated
assign/rest helpers, and shared helper deduplication. Trace helpers use
stable records as the built-in helper singletons do. Rust compares complete
traces, retained roots, declaration flags, diagnostic emptiness, and helper
ownership twice. The ES5 adapter joins original parse-tree coordinates to
the pinned checker's `isDeclarationWithCollidingName` answers; the fixture
preserves `undefined` versus `false` and the Rust bool seam consumes their
truthiness. Those queries use the original options and a hermetic `/lib`
mount. Other resolver methods keep their typed unavailable result.
A failure control checks disposal after a later bundle
member fails. The fixture also retains TypeScript's bundle printer bytes as
future references and hashes the complete 55-case Program observation
fixture. This packet does not compare bundle output bytes or alter runtime
admission.

## Shared-writer script printer packet

The internal bundle printer now uses one `TextWriter` for all global-script
members. The ordinary transformed-source worker accepts that caller-owned
writer; ordinary output still creates and finishes its own writer and map
recorder. Bundle-specific header work lives in `printer/bundle.rs`.

The header selects the first shebang in source order and emits each distinct
prologue value once before any source body. Deduplication uses JavaScript
UTF-16 values, including unpaired surrogate escapes, rather than the Rust
parser's lossy UTF-8 token value. Parsed literals reuse the existing lossless
template-fragment escape decoder; synthetic literals use their JavaScript
string metadata. Helpers retain their per-source stable priority order and
are deduplicated by name across the bundle. Explicit `ModuleKind.None`
emits each unscoped helper at its first requesting source; other module
values emit those helpers in the header. Source bodies skip their hoisted
prologues, including duplicate-prologue comments and the empty remaining
list's EOF comments.

`scripts/observe-bundle-printer.mjs` preserves 28 complete fresh Program
tuples, repeated twice. It covers source order, prologue identity/comments,
shebang selection, empty and erased sources, LF/CRLF, comment removal,
alwaysStrict, helper placement/deduplication, noEmitHelpers, importHelpers,
JavaScript input, and callback BOM/list metadata. ES5 resolver answers are
observed from the pinned checker with the original options, including the
absent-value distinctions for collision and referenced-collision queries.
The Rust adapter requires a matching original node for every query it uses;
other resolver methods retain their unavailable contract.

Rust compares the complete callback text bytes and final UTF-16 writer
position, line, and column twice. The frozen callbacks/diagnostics/metadata
and absent-versus-empty results remain runtime references; this internal
comparison does not claim Rust Program.emit tuple equality or admit outFile.
Declaration, external-module, JSON, and recorded bundle printing retain
typed refusals. Prepend/project references and custom-transformer API
ownership also remain unchanged.

The source owners are TypeScript 6.0.3 `writeBundle`
(`_tsc.js:117058-117070`), `emitHelpers` (`117719-117771`),
`emitSourceFileWorker` (`119753-119769`), prologue/shebang handling
(`119790-119840`), and empty `emitNodeList` (`120029-120072`). The pinned
native printer was checked at `printer.go:4667-4707` and `4738-4802`:
its ordinary source worker retains comparable prologue/list ownership,
but it has no outFile bundle path. Native removal is not the semantic
baseline for this 6.0.3 packet.
