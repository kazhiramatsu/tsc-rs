# H2.7d bundle output

Status: planning foundation, 2026-09-07, based on `fd95c196` and the
[original candidate preparation](h2-7de-candidate-preparation.md). Bundle
runtime admission remains closed. This packet changes the existing typed
output planner; it does not claim compatible JavaScript/declaration bundle
emission, hosted acceptance, or H2.7d completion.

## Planning packet

The existing `EmitBundle`/`EmitRoot::Bundle` foundation already modeled one
bundle output unit, but its planner treated a targeted request as a one-file
bundle, included external modules under every module kind, resolved relative
outFile callback names to absolute paths, and retained JavaScript paths for
declaration-only requests. It also derived `.d.ts` paths by replacing any
last extension, which differs from TypeScript's supported-extension rule.

The planner now follows the pinned 6.0.3 branches:

- A nonempty outFile selects from the whole Program in source order,
  including for a targeted planning request. External modules participate
  only under AMD, System, or `emitDeclarationOnly`.
- Bundle output paths preserve the raw outFile spelling. `outDir` and
  `declarationDir` do not relocate bundle members. Declaration-only output
  has no JavaScript or JavaScript-map member.
- Declaration paths remove only the supported case-sensitive extensions,
  testing compound declaration extensions first. Ordinary and forced
  planning share the same path worker. A forced `.d.ts` path does not imply
  a declaration-map path when neither declaration nor composite is enabled.
- Forced declaration plans retain the ordinary Program's collision
  diagnostics and blocked paths. The forced projection removes JavaScript
  members while preserving the bundle root and source order.

Relative callback names remain distinct from canonical collision keys.
The existing overwrite and duplicate-output owner checks both members before
emission. No-output and empty-string outFile cases retain their absent-path
distinctions. JSON eligibility recognizes a nonempty outFile.

A planning host without syntax can still select non-bundle sources and
bundle sources when the module filter is disabled. The bundle global-script
filter requires the Program's parsed `external_module_indicator`; missing
syntax returns `CheckedSyntaxUnavailable` instead of assuming that the
source is a global script. This does not add a syntax requirement to the
previous non-bundle planning protocol.

The compiler's preparation host supplies no syntax. Its common-source-
directory projection now calls the shared `sourceFileMayBeEmitted` predicate
directly, matching `getCommonSourceDirectory2`, so external modules remain
directory candidates even when outFile would omit them. This also preserves
the production option-refusal order before checked planning begins.

The option, output-plan, transform, and printer runtime refusal boundaries
remain in place. In particular, planning a target does not admit the
ordinary targeted Program API owned by H2.8d. Prepend and project-reference
inputs retain BLD1 ownership; no runtime option is dropped to bypass these
boundaries.

## Observations and comparison

`scripts/observe-bundle-plan.mjs` records 55 cases: 52 focused controls and
three unchanged original compiler inputs joined from the candidate census:

- `blockScopedClassDeclarationAcrossFiles.ts#default`
- `constDeclarations-useBeforeDefinition2.ts#default`
- `declarationFileOverwriteErrorWithOut.ts#default`

The census generator independently reconstructs original units, roots,
options, and source hashes before the observer runs. The observer retains
those three inputs without applying focused defaults. It mounts only the
recorded virtual inputs and pinned standard libraries under stable `/lib`
names; physical fallback cannot introduce an unrelated source.

Each fresh Program performs ordinary emit followed by forced
declaration-only emit, then diagnostic getters. The entire sequence repeats
in another fresh Program. The fixture preserves every callback's bytes,
order, path, BOM, source-file list, and metadata; all diagnostic streams;
`emitSkipped`; and absent-versus-empty emitted-file/source-map results.
Map bytes and the controlled sink failure are retained as future runtime
references, without counting them as Rust runtime comparisons.

The forced `declarationMap: true, declaration: false` control records the
6.0.3 `Debug Failure.` exception and its partial writes. Upstream's effective
declaration-map path gate and raw declaration printer-map flag disagree in
this case. The observer accepts that exception only for the exact control
and does not supply a missing declaration option.

Rust compares source selection, every output-path slot, source order,
ordinary/forced root kinds, collision diagnostics, and blocked-path state
twice for all 55 cases. Separate controls verify missing-syntax behavior
and the continuing outFile refusal before resolver use, activity, or writes
at the emitter entry.
The comparison uses an emitter host populated with the independently
observed Program order; this packet does not claim Rust Program-order or
bundle-output equality. These 55 cases do not enlarge the original 325-case
H2.7d/e union or its admitted count.
