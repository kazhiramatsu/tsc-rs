## A1 amendment: Unicode export names

The first production replay executes 26 of the 34 complete witnesses exactly.
All eight text-policy windows expose the same prior module-transform defect:
the private `is_identifier_export_name` accepts only ASCII, so `export const 名`
prints a quoted preinitializer and an invalid unquoted element-access assignment.
The expected form is `exports.名` in both places. The original fixture is unchanged.

A1-6 extends allowed production files to `crates/emitter/src/builtins.rs`, only
`is_identifier_export_name` and `CommonJsVisitor::create_export_access_from_name`.
The first delegates textual name validity to the existing Unicode-aware
`tsc_syntax::is_identifier_text`; the second selects element versus property
access from the actual name node's StringLiteral versus Identifier kind,
matching `createExportExpression` at `_tsc.js:111805–111851`. Source-map range,
extended-escape normalization and parsed name provenance remain unchanged.
No text replacement, new binding allocation or printer change is involved.
The existing helper's CommonJS preinitializer, named re-export and System
destructuring callers remain on the same factory paths.

The amendment pins `isIdentifierText` at `_tsc.js:8676–8687` and the module owner
above; its before implementation is pinned from the same base. The node-aware
access keeps string-literal export provenance distinct from textual identifier
validity; it does not infer a source node's kind from text.
