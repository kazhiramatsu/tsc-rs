## F1：arena をまたぐ node-name cache の衝突 — 修復（DESIGN §5 決定 16）

- 原因はレビューのとおり：`CarriedGeneratedNames::node_names` が `TransformNode`（arena 内番号）だけを
  key にしていた。`CarriedNodeKey { arena: TransformArena::id(), node }` に変更し、
  `TransformArena` の `Default` を `new()`（process 一意の id）にした（`derive(Default)` は id 0 を配って
  いた。`clone` は元から新 id）。裸の `TransformNode` は持ち越さない。
- 対照：direct `lifecycle/cross-arena/{node-derived-same-node,numbered}/{same-text,other-text}` と
  `cross-arena/{scoped,file-wide,file-level,temp}/same-text`（8 row）。上流 `x_2` / `y_1` に一致
  （main の既存差 `x_1` も閉じた）。

## F2：同じ binding の再印字で名前が変わる — 修復（決定 16）

- `autoGeneratedIdToGeneratedName`（`_tsc.js:120624-120632`）に当たる
  `binding_names: BTreeMap<CarriedBindingKey, String>` を追加。`note_generated_identifier` が全 domain で
  記録し、finalizer は割当の前に参照する（cache hit は集合・ordinal を進めない）。temp の ordinal は
  失敗を繰り返しても binding ごとに 1 回（`named_by_earlier_print`）。node 由来の temp も binding cache
  で同じ綴りに戻る。
- 対照：`reprint-after-failure/<6 kind>/{before,after}-statement-1`（12 row）、`double-failure/<5 kind>`
  （5 row）。上流と一致（`x_1` / `_s` / `_o` / `_m` / `_a`、double-failure 後の次の temp は `_b`）。
- レビューの probe（`run-failure-name-probe.py`、7 row × 2 回）を修正後の worktree に対して実行：
  7 / 7 exact（[records/after6/integration-probe/receipt.json](records/after6/integration-probe/receipt.json)、
  レビュー時点は 1 / 7）。

## 項目 2：bundle / temp ordinal / scope stack の近似 — fault controls で確認し、正確な model に置換（決定 17）

- 上流観測（direct `scope-fault`：root の binding 2 つ + 関数内 1 つ + 関数後 1 つを持つ source file
  print で、関数内 / 関数後 / 末尾後に失敗、次に standalone print）：temp は `_b` / `_d` / `_d`、scoped は
  `_s_4` / `_s_3` / `_s_3`。`file-after-failure`：失敗後の source file print の temp は `_a`。
  `bundle-fault`：最初の source で失敗すると 2 番目の source の名前は未生成（file-wide `_o_1`、numbered
  `x_2`）。決定 4 の「root に集約」「bundle 開始時に全 source を記録」はこの 6 row で上流と違っていた。
- 置換：printer が tsc の `pushNameGenerationScope` / `popNameGenerationScope` と同じ点で scope stack を
  追跡し（完了時だけ pop）、失敗時に最内 scope の `tempFlags` と open な scope の `reservedNames` の和を
  持ち越す。source file / bundle の print は新しい scope から（temp 0）。bundle の root 宣言名は各 source の
  worker 入口で記録。25 row（scope-fault 15、file-after-failure 5、bundle-fault 5）すべて上流と一致。
