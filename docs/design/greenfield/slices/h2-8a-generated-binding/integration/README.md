## 統合前に修復する二つの問題

### F1: arena をまたぐ node-name cache の衝突

`CarriedGeneratedNames::node_names` は `TransformNode` だけをキーにする。
`TransformNode` の source / node 番号は arena 内の識別子なので、別の transformation が同じ番号を持ち得る。
`Printer::note_generated_identifier` が前の original node の綴りを保存し、
`finalize_generated_binding_names_with_policy` が次の arena の node にそれを返す。

`x` から生成した宣言の after hook を失敗させ、同じ printer で別の transformation の
`y` から生成した宣言を印字すると、TypeScript / main は `y_1`、提出候補は `x_1` を出す。
fresh printer では候補も `y_1` になる。単なる suffix 差ではなく、異なる元の名前が置き換わる。
同じ文字列 `x` の別 arena でも、TypeScript の `x_2` に対し候補は cache hit して `x_1` を返す。
後者は main にもある未修復差、前者は今回の回帰。

上流は `_tsc.js:120633–120637` の `getNodeId(node)` が表す node identity を使う。
修復は cache の寿命をまたいで identity を保持すること。既存 `TransformArena::id()` を用いる場合も、
`new` / `clone` / `Default` の一意性を確認し、arena を識別しない裸の `TransformNode` を持ち越さない。

### F2: 同じ generated binding を失敗後に再印字すると名前が変わる

`CarriedGeneratedNames` は集合・temp ordinal・node-derived cache を保持するが、
上流の `autoGeneratedIdToGeneratedName` に対応する binding 単位の cache がない。
同じ synthetic identifier を再印字しても、finalizer は持ち越した集合に衝突する別名を割り当てる。

最初の宣言を印字した直後に hook を失敗させ、同じ printer で同じ宣言をもう一度印字すると、
候補は numbered `x_1 → x_2`、scoped `_s → _s_1`、file-wide `_o → _o_1`、temp `_a → _b`。
TypeScript と main は四つとも最初の綴りを維持する。file-level `_m` は隣接の一致 control。

上流は `_tsc.js:120624–120632` で node-derived と autoGenerate ID の cache を分ける。
再印字や clone は同じ binding identity の綴りを再利用し、新規 binding だけが集合・ordinal を進める必要がある。
temp は失敗を繰り返しても同じ binding を再加算しないこと。成功後の reset と fresh printer は既存の対照を維持する。
