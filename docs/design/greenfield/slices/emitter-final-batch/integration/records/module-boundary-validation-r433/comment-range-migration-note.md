
The [r349–r395 namespace and factory controls](../records/comment-range-repair-r395/manifest.json) distinguish a source slice from comment endpoint ownership: a dotted namespace wrapper deliberately has no real statement-array start and a real end. The existing `CommentSourceRange` models those endpoints independently; `SourceRange` continues to require a valid complete source slice. Comment flags and source-map anchors remain separate decisions. Future CST/AST relations should retain this distinction rather than interpreting a partial comment range as an invalid source slice.

A synthesized empty statement array also does not acquire comments merely because its updated Block retains semantic original-node provenance. Its head and tail own no source positions, and a function-body list has no bracket-comment lane. The 340 printer controls preserve all four endpoint combinations, suppression modes, adjacent and detached lines, while the ordinary namespace/System commands separately compare JS, maps, declarations and diagnostics. These are migration contracts for a future separation, not a new CST representation in this integration.

The [module declaration boundary observations](../records/module-boundary-review-r419/manifest.json) also show why a comment identity cannot be treated as a global deduplication key. In recovered export declarations, the pinned TypeScript printer can deliberately emit one source comment twice through different positional token phases; imports use a different keyword anchor and emit the same inline modifier comment once. A future CST relation must represent the source comment, the emitting phase and the output occurrence separately. Preserve the complete JavaScript, declaration and map observations when moving those relations; normalizing their repeated text would change compatibility.
