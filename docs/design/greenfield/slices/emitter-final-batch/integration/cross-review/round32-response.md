## r32: MissingDeclaration correction, revised proposal

**Your correction is confirmed at source.** `visitEachChild` (_tsc.js:91318-91323) returns the node itself when `visitEachChildTable[node.kind]` is undefined, and the table has no `283` entry; `createMissingDeclaration` (23670) is a bare `createBaseDeclaration` with zero transform flags, and both parser sites attach `modifiers` without recomputing them. I reproduced the after-visitor probe and extended it with a spread call, an async arrow and an optional chain as decorator expressions: in all four mode/target combinations the `MissingDeclaration` survives the built-in pipeline with `transformFlags=0` and its `Decorator` modifiers intact, the output is only the class-expression statements, and no `__spreadArray`, `__awaiter` or optional-chain temporaries appear. My r28 statement that `modifierVisitor` drops the decorators was wrong: no pass ever reaches them because no pass has an operator for the parent and every flag-gated visitor sees zero.

**Why (A) alone is not enough in Rust.** `propagates_transform_child_flags` (builtins.rs:17041-17050) feeds `FactoryTransformChildren::of` (16584), so adding `MissingDeclaration` there reproduces tsc's zero flags (own flags are already `NONE` via the `_ => {}` arm of `local_transform_flags`). But three visitors descend through `try_visit_each_child` with no transform-flag gate at all: the ES-module visitor (builtins.rs:2087), JSX (jsx.rs:364) and System (system.rs:2515); the TypeScript visitor gates on `CONTAINS_TYPE_SCRIPT` (11504-11513), es2017/es2018/class_fields/generators gate on their bits, and I could not see a gate in es2015/es_next/legacy/standard within their entry windows. Any ungated pass would visit the retained decorator expression: JSX could insert the `react/jsx-runtime` import for `@(<div/>)`, the ES-module pass would rewrite `import.meta` or dynamic import inside it, and any lowering could request helpers or hoist temporaries even though the parent prints nothing. So flags parity plus a structural identity rule are both required.

**Recommended: A + B, no per-pass early returns.**
1. A: add `SyntaxKind::MissingDeclaration` to the `propagates_transform_child_flags` exclusion. This also keeps the enclosing statement arrays' aggregated flags equal to tsc (`compute_transform_flags` folds child flags into array flags at 16447-16455), so enclosing blocks are not visited for a decorator-only reason.
2. B: an emitter-local child mapper `try_visit_transform_children(data, visitor)` that returns `Ok(())` for `NodeData::MissingDeclaration` and otherwise delegates to `syntax::try_visit_each_child`, then replace the 31 direct call sites in the emitter (builtins.rs 8, es_next 3, legacy 3, standard 4, system 3, es2015 2, one each in class_fields/es2017/es2018/es2021/generators/jsx/factory/declarations/subtree). The syntax crate helper stays untouched for the checker and type builder. This is the exact analogue of "no table operator": identity in every pass, modifiers retained, no eliding.
3. Printer: keep the statement and expression `MissingDeclaration` arms as no-ops inside the ordinary comment/map phases; never `NotEmittedStatement`.
4. Factory: nothing to recompute; because B makes the node identity, `update_node`/`clone_node` never see it. `factory.rs`'s own `try_visit_each_child` call goes through the wrapper as well so a future generic clone cannot descend.

(C) would need one early return per pass that lacks a gate today plus vigilance for future passes; B covers all of them at one seam. (B) without (A) would be output-correct but leave array-level flag facts different from tsc.

**Controls (complete commands, both decorator modes, ES5/ES2015/ESNext, module commonjs/esnext/system, maps on).** Decorator expressions that must emit nothing and request nothing: `@g(...[1])` (no `__spreadArray`), `@(async () => { await 1; })` (no `__awaiter`/`__generator`), `@(g?.a?.())` (no hoisted `_a` temps), `@(import("x"))` (no `Promise.resolve().then(require)`), `@(import.meta.url)`, `@(tag\`x\`)` at ES5 (no `__makeTemplateObject`), `@(class { #p = 1 })` (no `__classPrivateFieldGet`/WeakMap hoist), and in a `.tsx` with `jsx: react-jsx`, `@(<div/>)` (no runtime import). Plus the original two shapes and the comment/map matrix from r28. Negative: expression-position `x = @g<number> foo;` remains refused.

**Admission rule stands as in r28**, with one adjustment: match the reachable `MissingDeclaration` by `node.end == missing.position` (end is the creation full start; `pos` is widened), and do not require anything about its modifiers' contents, since they are opaque by construction.
