## r28: MissingDeclaration shape

**Upstream path (both rows, both `experimentalDecorators` values).** Parser: `parseDeclarationWorker` creates the node at the current full start with `Declaration_expected` (report-at-position, length 0), then `setTextRangePos(missing, pos)` widens `pos` back over the decorators; `end` stays at the creation full start. Tree: `Block[MissingDeclaration{modifiers:[Decorator]}, ExpressionStatement(TypeAssertion(<number>, ClassExpression C))]`. Transform: `transformTypeScript` reaches the node through `visitEachChild`, whose modifier visitor returns `undefined` for every `Decorator` (`isDecorator(node) ? void 0 : …`), so `g<number>` / `g()` are dropped before esDecorators or legacyDecorators ever run; nothing is evaluated. The type assertion is erased and the class expression stays a class expression statement (hence the printed `;`). Printer: `emitWorker` has `case MissingDeclaration: return;` in both the statement and expression hints (117464 / 117678), reached *after* the comment and source-map pipeline phases, so it is not a `NotEmittedStatement`: leading comments at `pos` and a zero-length mapping at `pos`/`end` are still produced, and `emitList` writes no blank line because `writeLine` is a no-op at line start.

**Rust path today.** Parser matches (parser.rs:2495-2508 and 6087-6098 set `node.pos = pos` and `modifiers`; `end` remains the creation full start, which is what the recorded `missing_node.position` holds). Emitter: no `NodeData::MissingDeclaration` arm anywhere. The statement worker's `_ if !changed` fallback (printer.rs:2836-2847) would print the original source slice `@g<number>`, and the expression worker has the same fallback (8158-8166); both are wrong for this kind. The TypeScript visitor has no explicit arm either, so whether its generic child visit drops `Decorator` modifiers on a `MissingDeclaration` must be checked, because the standard-decorator pass treats the kind as a left-hand-side expression (standard_decorators.rs:8194) and any surviving decorator would be a candidate for lowering, which would evaluate `g()`.

**Smallest implementation.**
1. Printer: explicit `NodeData::MissingDeclaration(_) => Ok(())` in both workers, placed before the `!changed` fallbacks, leaving the ordinary comment/source-map phases untouched.
2. TypeScript visitor: an explicit `MissingDeclaration` arm that visits modifiers with the modifier visitor (decorators elided, other modifiers kept) and returns the node; if the generic path already does this, a unit test pinning "no decorator survives, no `__decorate`/`__esDecorate` request" is enough.
3. No `NotEmittedStatement` substitution, no eager modifier erasure at parse time.

**Admission rule (structural).** Extend the r27 predicate with a second admissible missing kind: event `Diagnostic(Parser)` with retained diagnostic and `missing_node.kind == MissingDeclaration`; in the reachable walk, match a `MissingDeclaration` node by `node.end == missing.position` (not `pos == end`, which no longer holds after widening), require a unique match, require its parent to own a statement list (SourceFile, Block, ModuleBlock, Case/DefaultClause), require all children to be modifier-like with no zero-width nodes inside, and keep "no actions". Expression-position `MissingDeclaration` (from `parse_decorated_expression`, `Expression_expected`) stays refused: it is followed by further recovery in practice and its emit (`x = ;`) has not been observed.

**Adjacent matrix (complete commands, both decorator modes, ES5/ES2015/ESNext).**
- Positions: original block form; top level; inside `namespace N { … }`; inside a module (`export {}` first).
- Decorator shapes: `@g<number>`, `@g()<number>`, `@a.b<number>`, two stacked decorators.
- Comments: `/*a*/ @g<number> /*b*/ class C {} // c`, a line comment on its own line before `@`, a trailing comment after `}`.
- Source maps on for every row (the zero-length mapping at the missing node and the class-expression statement that follows at the same generated position).
- ES5 class-expression lowering with the trailing `;` (`(function () { … }());`).
- Negatives that must stay refused: `x = @g<number> foo;` (expression position), `@g<number>` at EOF, `@g<number> function f() {}` (MissingDeclaration followed by a declaration, check whether tsc also drops nothing else).

**r27 correction accepted.** `async () => { await` at EOF also records a report-only `}` expectation, so it is a negative control for the strict predicate, not a positive one. This does not affect the MissingDeclaration rule above.
