# Follow-up: isolate emit and diagnostic responsibilities

Status: post-integration design investigation, not a refactoring authorization for the current closure train. Requested by the user on 2026-09-19 after the r101 boundary audit. Current work stays limited to demonstrated compatibility defects and final qualification.

The r101 audit demonstrates coupling between transformation provenance, comment ownership, text emission, temporary-name assignment and source-map recording. A valid text range does not imply a parsed original; an original node does not donate every comment/map flag; a synthesized parenthesis owns boundaries independently of its child. These distinct meanings are carried through shared node metadata and printer paths, making small corrections require broad regression checks.

A future design should make those contracts explicit before moving code. Candidate boundaries are a documented transformed-node interface (including original identity, raw/comment/map ranges and generated binding identity), a text/token output interface, and independently testable comment/map consumers. Output locations remain a necessary shared fact between emitted text and maps. Shared mutable ownership and implicit phase ordering are candidates for removal, subject to measured compatibility and performance.

The checker/emitter dependency requires a separate source-level inventory. The current audit does not prove that the printer fixes changed checker diagnostic behavior; running checker regressions is a verification obligation, not evidence of such a change. Record actual call and data dependencies before deciding which interface should move.

Use the frozen complete-command cases and source-map suppression controls as migration contracts. Compare text, maps, diagnostics, callback metadata and failure behavior independently as well as together. Introduce one boundary at a time behind unchanged public behavior; retain the full integration gate. Do not combine that migration with current source corrections or weaken exact comparisons.

Concrete starting evidence: `round103-opus-response.md`, `round104-opus-response.md`, `native-r101-final-differences.json`, and the r104 complete-command controls. No implementation choice or milestone closure is claimed here.

The r107 declaration controls provide a second boundary example: bundle JS emission snapshots and restores parsed metadata for the later declaration phase, while per-file emission clears it. The erased type range can therefore remain available to declaration comment ownership only in a bundle. The exact upstream duplication before a type annotation is intentional in the initialized case (see `r107-declaration-comment-controls.md` and `round107-opus-response.md`). A refactoring must give each output phase an explicit metadata lifetime instead of assuming one global cleanup rule.

A source-level follow-up at Recovery HEAD `aea09cbaf2015a5eef7869fc4888042f9784bf3c` confirms a real checker-to-printer dependency: `crates/checker/src/declaration_emit.rs::symbol_to_string_via_node_builder` builds a display node, then uses `create_printer` with comments removed, declaration syntax and a single-line standalone writer. This path supplies declaration diagnostic symbol text. The `EmitResolver` adapters in `crates/checker/src/emit.rs` also accept emitter-owned arena, tracker and node-builder types. Thus both shared interface types and a runtime rendering dependency need inventory. These findings do not demonstrate a new diagnostic regression from the current comment fixes. A future boundary proposal should distinguish diagnostic display formatting from JavaScript/declaration emission while preserving their explicitly shared syntax contracts.

The [r127 transpile check](r127-transpile-results.md) and [r128 variable-recovery review](r128-remaining-transpile-review.md) provide another concrete boundary: `preflight_source` uses one parser recovery-admission result for emit consumers. Admitting an empty type annotation therefore requires checking erased JS, retained declaration syntax, declaration maps and diagnostic behavior together. A future design could make each consumer's required facts explicit and compose them in command preflight. It must preserve the current all-output refusal/partial-write contract; separating consumers does not justify emitting JS before discovering that the requested declaration output cannot be produced. The current candidate changes no phase interface and is not evidence that such a refactoring is already safe.

The user subsequently proposed a clear CST/AST separation and indirect references between them, explicitly as a future large refactoring. Investigate an immutable concrete-syntax store for tokens, trivia and original spelling; a semantic/transformed AST; and stable identities with explicit relation tables. Semantic provenance, comment transfer and source-map origins must remain separate relations, with support for splitting, merging, omitted nodes and generated nodes without source counterparts. This is a design direction to evaluate, not a claim that one-to-one links suffice or that a concrete representation has been selected. Include lifetime/incremental invalidation, memory and lookup costs in the investigation.

The r157 failures provide a concrete migration contract: an ES2015 renamed binding needs its semantic original for resolver identity without copying the original's erased-type comment metadata; a CommonJS export plan needs the pre-substitution spelling while emission needs the generated binding; a for-of declaration list needs its own trailing-comment boundary. Preserve these distinct relationships and complete output tuples when introducing indirection. The current fixes remain in the existing architecture and do not begin this migration.

The [r342 System controls](../records/body-comment-review-r366/manifest.json) distinguish three additional relationships: the current statement array's source range, a relocated list's detached-comment resume, and a token map continuation beyond a real EOF. The latter is a generated mapping coordinate; it does not authorize an out-of-bounds AST position or comment cursor. A future relation table must preserve these independent meanings instead of treating one original-node link as an all-purpose range donor. Explicit `alwaysStrict` variants and empty/erased lists are migration controls for this distinction.

The [r364–r372 printer-state controls](../records/body-comment-validation-r374/manifest.json) distinguish a returned string's physical end from the writer's next generated position, which includes pending indentation. After an interrupted function body these differ even when returned text and events match exactly. They also fix the function body's detached head and tail outside its own nested-comment suppression extent, with restoration on success but retained state on failure. Refactoring must specify both normal and exceptional lifetimes; one shared cleanup policy would change observable behavior. The current correction aligns the test adapter's measurement with TypeScript and leaves the shared writer's map coordinates intact.
