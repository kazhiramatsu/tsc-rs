# Creation-order System lexical hoists

Codex independently confirmed round47 against TypeScript 6.0.3 `_tsc.js` 112605–112731 and 112932–112948. Its lexical environment is an ordered list, not a name set: an initialized destructuring leaf requests its hoist after the default-value temporary; later uninitialized declarations, imports and classes follow it. The old prepass cannot reproduce this. The existing `used_names` set continues reserving spelling independently.

Implementation removes the hoist prepass and root-temp table. Helper import remains a one-time prefix. Ordinary imports, import-equals, classes, uninitialized binding names, initialized leaves and temporary assignments request hoists at their visitor/creation sites. Uninitialized for patterns flatten against `void 0` then request binding hoists again, as upstream does. Class binding metadata moves to the class visitor. The unexplained `default` string skip is removed: anonymous default class bindings are generated names, not a special variable binding named `default`. Nested function declaration bodies continue using the expression visitor, which does not hoist their declarations into the module.

Temp assignment ranges use VariableDeclaration / BindingElement / ComputedPropertyName locations, separate from the semantic original on returned binding assignments. The same flatten path now follows upstream for empty-pattern root identifier reuse, computed-key temporaries even without rest, and non-simple nested default values. These are exercised in the same 198-case complete-command matrix rather than hidden behind KNOWN entries.

The additional all-omitted input `export let [,] = source` crashes TypeScript 6.0.3 itself in `inlineExpressions(undefined)`. The failed observer receipt r47b is retained. A direct upstream reproduction confirmed this; the all-omitted control now uses `get()` (which needs a temporary and emits normally). This is not claimed as compatibility coverage of the upstream exception. The original 72 and 126 observations remain immutable in the expanded matrix (checked by case ID).

Other ordinary corrections reviewed in rounds44–46 remove the unsupported original/range donor from captured `arguments`, retain the parsed `super` property-name node, and remove the direct-export statement name-range override. The access-level source range remains. Native complete comparisons and broader regressions are pending; no recovery KNOWN has been retired.
