**A verified, B verified with one correction to the proposed repair.**

**A. Direct export access range.** Upstream ranges the access to the parsed name on both direct paths: the function/class-initializer branch of `visitVariableStatement` (_tsc.js:111569-111575) and `transformInitializedVariable` both do `setTextRange(createPropertyAccessExpression(exports, variable.name), variable.name)` and reuse the parsed name as the child. The printer then emits `/** leaf */` from the access's own leading phase and sets `containerPos` to the name's pos; the name child starts at the same pos and is suppressed by `forEachLeadingCommentToEmit`. Rust `create_export_access_from_name` (builtins.rs:10840) leaves the access synthetic and only sets source-map metadata, and `comment_range_for_node` (printer.rs:16477) falls back to raw pos/end, so the access has no leading phase and the retained child prints the comment after `exports.`. The proposed `set_text_range(access, name)` is the exact upstream shape. No reason to avoid the raw range: the source-map donor is the same range, so the existing `set_source_map_range_from` becomes redundant but harmless. Trailing side is also upstream-consistent: probe `export let { /** leaf */ x /* t */ } = source` prints `exports.x /* t */ = source.x` at ES5 and ES2015, which requires the access to own the name's end. The extended-escape branch is unaffected because the access, not the normalized child, carries the range. The `default` shape's second `/** default */` inside the parenthesized temp assignment is already produced by Rust and matches TS.

**B. PropertyAssignment initializer comments.** Upstream `emitPropertyAssignment` (119516-119526): `emit(name)`, `:`, space, then `emitTrailingCommentsOfPosition(initializer.pos)` with no prefixSpace, then `emitExpression(initializer)`. Two different guards apply. The trailing-of-position pass is guarded only by `containerEnd`/`declarationListContainerEnd` (121208-121216). The initializer's leading phase is guarded by `containerPos`. Producer: `visitShorthandPropertyAssignment` sets the PropertyAssignment's range to the shorthand node, and `substituteExpressionIdentifier` sets the `exports.x` range to the name, so initializer pos equals the container pos and its leading phase is suppressed. Rust's worker (printer.rs:5163) runs `emit_intervening_comments_before_node` then `emit_leading_comments_for_node_worker` with no container guard, hence the duplicate.

**Concrete counterexample to the proposed skip.** Do not skip the intervening emitter when the parent owns the prefix. tsc itself prints the comment twice in the same-line form because the trailing-of-position pass ignores `containerPos`:

```
export let x; ({ /** c */ x } = source);
// ES2015 CJS tsc output:
({ /** c */ x: /** c */ exports.x } = source);
```

The newline form prints once only because the same-line scan finds nothing. So the least-impact correct repair is: keep the intervening call unconditional; compute the owned prefix with `parent_comment_container_owned_prefix_for_owner(expression_context.comments().container_pos(), owner)`; pass `owned.or(skipped_prefix_bytes)` as the resume to the leading worker. Owned must take precedence, because its `next` is the whole leading-trivia end: for `x: /* a */\n /* b */ exports.x` upstream prints `/* a */` (trailing-of-position) and never `/* b */` (leading phase suppressed), and a resume ending after `/* a */` would let the leading worker print `/* b */`. Trailing logic stays as is. The alternative of switching to `emit_required_node_with_context_and_source_extent` is not a fit: it transfers the container-owned prefix via `deferred_container_scope`, but it has no trailing-of-position pass and would change the colon anchor flow.

**Two controls for B beyond the fixture:** the same-line duplicate above (must stay duplicated), and the mixed `/* a */` newline `/* b */` form (one comment). Any other worker that pairs `emit_intervening_comments_before_node` with `emit_leading_comments_for_node_worker` has the same missing guard; a grep for that pair is worth one look after this lands, but is outside this repair.
