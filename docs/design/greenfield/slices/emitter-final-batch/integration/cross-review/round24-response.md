## r24 review: flaws found and corrections

**FULL-start refinement: confirmed, it avoids a real bug.** `create_missing_node` allocates at `scanner.full_start_pos()` (parser.rs:1257-1262) while a non-EOF report goes through `parse_error_at_current_token` at `token_start` (937-946). `await /*c*/)` or `[await\n]` would make a diagnostic-start match miss the node. The EOF path (`report_at_current_position`) and `SilentMissingNode.start` (1247) already use full start, so recording `{kind, full_start}` on the new event makes all three consistent. Returning `(diagnostic_index, event_index)` from the reporting helper is the right ownership: the event exists even on same-start dedupe (9915), and the index is always ≥ any live checkpoint, so JSDoc/`try_parse` truncation reverts it.

**Fresh vs incremental for valid top-level await: no equality flaw in the proposal itself.** Both paths reach the same `reparse_top_level_await` call (10128-10141) with runs derived from node flags, and `consume_node` leaves `full_start_pos` at the consumed node's end, so `Reparsed{start, end}` matches the fresh parse. Recording `end` before `scanner.restore` is required, as you state.

**Two corrections, both small.**

1. Incremental reuse rule. Rejecting a candidate that intersects a skip's *token span* is necessary: a skipped token sits between nodes but inside an enclosing node's range (a Block containing the skip), and reusing that Block would silently drop the skip, breaking record equality. Rejecting on the *whole Reparsed range* is not necessary for equality: the run is re-executed unconditionally, first-pass reuse inside it is already blocked by the context-flag mismatch (old nodes carry `AWAIT_CONTEXT`), and reparse-pass reuse produces no records inside reused nodes. It only removes reuse for every valid top-level-await module, which the incremental stress lanes measure. Smallest correction: reject on skip spans (plus the existing event-start rule); leave Reparsed out of the reuse gate unless an equality test fails.

2. Missing-record matching in the later admission. Two reachable zero-width Identifiers can share one full-start (nested recovery chains). Require a unique reachable match per record, and the converse: every reachable zero-width Identifier not flagged `JS_DOC` must correspond to exactly one record. Any mismatch refuses. This also closes the unreachable-speculative-node concern from the arena side.

**Confirmations.** `is_literal_only` ignores actions, so clean and literal-only modules with `Reparsed` actions keep today's admission. Retaining `TokenSkipped` by `statement_start` is consistent with events' `reparse_start` (9922); top-level no-progress skips outside any statement carry their own start, which the range filter still handles. Retaining `Reparsed` by start is fine given the single pass. JSDoc materialization runs after the reparse and each comment restores the checkpoint, so actions appended there are truncated. Action order is deterministic: retained skips, then live run records, then `Reparsed`.

**Nothing else to change.** The 24-row predicate as stated (Identifier operand of `AwaitExpression`, retained diagnostic, no actions, all other events literal) is a producer/AST predicate and stays refusing the 8 skip rows, the 2 MissingDeclaration rows, the 2 reparse rows and the 12 malformed-comment controls.
