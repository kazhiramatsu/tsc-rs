## 3. Implementation and validation record

The first two regressions reproduced the reviewed differences before production
changes: private-storage prefixes on a cloned anonymous class, and single quotes
in a reused import type's generated declaration. Together the test bodies took
1.57 s; initial dev and test compilation took 2m37s and 1m49s respectively.
The tests now live in the already registered `h2_7b_w5b_controls.rs` module and
reuse W4-A's complete frozen-observation assertion.

Implemented mechanisms (hosted full-corpus validation required before landing):

- Import type: reuse the StringLiteral child before deciding whether its
  LiteralType parent can be reused (`_tsc.js:133526-133535`).
- Private storage: use the current class node's declaration/assigned-name
  provenance (`_tsc.js:96921-96945`, `11562-11583`); keep the broader runtime
  named-evaluation query for helper placement.

- JSDoc overloads: distinguish direct array/cache property presence from
  nonempty attached documents. Both signature collection and implementation
  compatibility use property presence, as upstream does.
- Negative literal annotations: check the positive operand first, preserving
  the regular/fresh type allocation sequence before negation.
- Any-base indexes: preserve the singleton's identity through retaining copies,
  clear it on fresh IndexInfo construction (including widening), and exclude
  only that singleton from synthesized declaration indexes.
- Tuple lengths: allocate and retain the length type before the tuple target,
  then attach it when the checker materializes member symbols.
- Comment ownership: synthetic multiline list elements execute their own
  leading/trailing phases; block first statements respect inherited prefix
  ownership. A JSDoc signature inside leading trivia does not inherit the
  containing statement's detached prefix in addition to its copied comment.

Intermediate results: the first five cases reached 4 exact observations, with
one extra JSDoc leading comment remaining before the comment ownership change.
Emitter private controls: 16 passed (0.01 s); types library including eager
length construction: 30 passed (0.01 s, build 20.86 s).

New J10 evidence: `_tsc.js:71739-71747` excludes `isThisIdentifier(left)` before
calling getResolvedSymbol. Rust currently omits that exclusion as well as the
cold-cache resolution call. The previous 21 false positives include typeof-this
queries, where the parser represents `this` as an Identifier. Port both upstream
operations together and rerun the named guards and diagnostic conformance;
do not suppress diagnostics or invent a different resolver for this case.

Focused result: all 16 targeted residual cases match complete frozen
observations, and the previous wave's controls pass. The combined compiler
run (targeted rows plus CLI, emit-session, filesystem loader and H1 I/O
contracts) passed 85 tests in 35.83 s; 10 existing Node-oracle audits remained
ignored. Build time was 2m30s. A preceding 15-case result exposed the secondary
array-export failures documented below.

The auto-accessor producer now preserves synthetic positions on backing/get/set
nodes, copies source-map ranges to all three, and assigns the comment range only
to the getter. ES2015 lowering reads explicit comment ranges before raw ranges,
matching `getCommentRange`; this closes the third comment row without deduping
comments globally.

D2 new investigation: a scratch in-memory instrumented upstream library on the
minimal `thing.doit` source shows that its return-signature cache is still `any`
at completion. Its correct TS2339 display instead comes from syntactic return
serialization, which calls expression inference on the returned computed-name
object. The Rust diagnostic renderer's `syntactic_single_return_type_text_slice`
only supports assertion reuse and omits that route. This refines the old review's
cache-order hypothesis; no D2 production change has been made yet.

S1 secondary trace refines the old syntactic-builder hypothesis: the failed
factory operation is `index_info_to_index_signature_declaration_helper`, whose
name child came from another source. Upstream `getNameFromIndexInfo` returns
text, so this parameter should be created from that text. Before that boundary,
`combine_common_js_export_members` also omits `_tsc.js:56428-56433`: an unchanged
reference-shaped export clone preserves its symbol/type arguments as an alias.
Without that alias, an exported array is expanded as an anonymous object with
all Array members. Both producer repairs are implemented; the five S1 frozen
observations now all pass.
