## 5. Lane semantics — W-H2.7A study contract

W-H2.7A follows W-H2.6B/W-H2.6C: pinned TypeScript 6.0.3, fresh
processes, two observations per case, exact capture, no hand-authored
expected bytes. It runs in m-1, not in this authoring pass;
family/case totals are TO-VERIFY(m-1). Because H2.7a activates no
output, W-H2.7A is UPSTREAM-ONLY evidence, in TWO observation classes:

1. **Public observables** — `.d.ts` bytes, reported diagnostics,
   `emitSkipped`, emittedFiles order — captured from ordinary pinned
   upstream runs.
2. **Internal decisions** — resolver query results, NodeBuilder
   truncation/fallback choices, `declBlocked` composition — NOT
   exposed by ordinary runs; they require a PINNED INSTRUMENTED
   `_tsc.js` probe (or internal-test seam) with an exact trace schema
   and artifact hash, so the promised decision-equal ca replay is a
   defined comparison, never an inference from bytes.

Rust-side guarantees (refusal retention, dormancy) are NOT witness
lanes: they live in a separate zero-activation Rust control gate (the
§6 ca rung), keeping upstream observation and Rust controls distinct.
The frozen evidence replays through the dormant foundation at the ca
rung and again at the H2.7b activation.

| lane | W-H2.7A must confirm | W-H2.7A must falsify |
| --- | --- | --- |
| visibility/export graph | exported/aliased/re-exported members appear exactly; non-visible declarations elide; import elision and augmentation-required imports match | any member kept/elided differently, wrong alias form, or import retained/dropped divergently |
| type serialization | annotated types print syntactically; inferred types serialize through the NodeBuilder identically across repeated runs; literal/const values match | annotation-vs-inference arm swaps, non-deterministic serialization, wrong literal shapes |
| late-bound/computed names | late-bound members and index signatures serialize per `createLateBoundIndexSignatures`/`isLateBound` | wrong name form, dropped member, or invented signature |
| signatures/overloads/accessors | overload sets, implementation elision (`isImplementationOfOverload`), accessor pairing, optionality (`isOptionalParameter`/`requiresAddingImplicitUndefined`) match | merged/dropped overloads, wrong optionality or accessor shape |
| JS declaration synthesis | `transformDeclarationsForJS` output for allowJs+declaration cases, expando properties included | any divergence in JS-derived declaration shape |
| directives/references | triple-slash references, lib directives, and no-default-lib headers synthesize exactly | missing/extra/misordered directives |
| diagnostics channel | declaration-blocking diagnostics (the transform channel) and declBlocked/emitSkipped composition observed exactly (declBlocked via the instrumented probe) | any diagnostic difference or skip-state drift |
| printer grammar/shape | comment retention under onlyPrintJsDocStyle, helper suppression, newline/BOM behavior in `.d.ts` bytes, AND the declaration/TypeNode print grammar incl. parenthesization of composed types | any byte-shape or parenthesization divergence |
| NodeBuilder result contracts | truncation, error, and fallback behavior (:51205-51255) via the instrumented probe | wrong truncation point, silent fallback, or divergent error contract |
| symbol tracking/accessibility | symbol-tracker callbacks, accessibility verdicts, and module-specifier override behavior (:114280-114304, :50890-50927) via the instrumented probe | any tracked-symbol, accessibility, or specifier divergence |
| syntactic-builder arms | annotation/JSDoc reuse vs checker-inference selection, recovery, and fallback behavior | wrong arm selection or divergent fallback |
| generated/global names | `hasGlobalName`-driven collision behavior in declaration output | any collision-avoidance divergence |
| AST identity/provenance | node identity, original-node provenance, and transform-flag propagation through the declaration transform (probe-observed) | identity loss, provenance loss, or flag drift |
| upstream-observation controls | declaration:false and JS-emit-only adjacents stay untouched | any adjacent upstream behavior change |

A failed confirmation becomes a named owner/facet for the foundation
