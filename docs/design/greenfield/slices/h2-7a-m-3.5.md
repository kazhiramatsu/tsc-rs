**(c) Deviation record — the `declaration_syntax` printer option.**
Upstream's printer has no mode: it prints whatever TypeScript syntax the
tree holds, and the JavaScript lane sees none because
`transformTypeScript` erased it. The Rust JavaScript lane is different
in one respect the audit already recorded: several JS-shape arms erase
parse-tree TypeScript syntax BY OMISSION (Parameter :3857 never reads
`type`; class members never read `type`/`questionToken`; the erased type
lives in `EmitMetadata::type_node` for comment placement) while others
print it when present (`emit_signature_head` :7547 prints a return
type). Printing TypeScript syntax unconditionally would therefore change
the JS lane's behavior on any un-erased parse-tree node. The new arms
and the type/optional/definite/modifier fields of the JS-shape arms are
gated by `PrinterOptions::with_declaration_syntax(true)` (default
false): the production JS lane stays byte-identical BY CONSTRUCTION
(T0 100% / FP=0 unchanged is then a confirmation, not the proof), and
dormancy is a machine-enumerated allowlist (§6 L5). H2.7b sets the
option in the declaration lane. Recorded as a deviation under the
schedule §1 house rule (Rust structure follows the architecture, not
incidental upstream shape).

## 5. Design details (self-contained)

### 5.1 The option and the gate

`declaration_syntax` gates EXACTLY: the new arms (every `NodeData` kind

### 5.5 Comments under onlyPrintJsDocStyle (round-1 F1)

`shouldWriteComment(text, pos)` = `isJSDocLikeText || isPinnedComment`
