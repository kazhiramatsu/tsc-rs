# H2.6b / m-1 — orchestration lanes (roots, URL, inline payload, sourcesContent)

Status: design-gate packet for the first production rung of the
[h2-6b ladder](h2-6b.md#8-implementation-ladder). It lands the §4.2/§4.3
root-and-URL lane selection, the base64 data-URI payload builder, and the
`inlineSources` content feed — all BEHIND the four still-refused options,
so production behavior is byte-identical (corpus-inert) and the frozen
W-H2.6B witnesses are replayed through the harness-print bridge and the
lane functions directly.

## 8. Frozen witnesses and suite

W-H2.6B is the sole byte authority. Two tiers:

1. **Lane-level (emitter unit suite):** for every W-H2.6B case with an
   external map — construct the generalized recording inputs from the
   CASE options + paths exactly as production will, assert the
   generator replay (6a-m-1 machinery) reproduces the frozen
   `source_map_json` byte-for-byte (this now proves the lane selection:
   `source-root-shapes` cases prove lane 1 + the field form,
   `map-root-shapes` prove lane 2 incl. per-file nesting and the
   relative resolution, the 6a-lane cases prove lane 3 regression);
   for every case — assert `source_mapping_url` reproduces the URL
   substring frozen in the js write (data URI for inline cases,
   encodeURI'd forms for external), and for inline cases assert
   `base64_encode` round-trips the payload against the frozen
   `source_map_json`. base64 vectors (empty/1/2/3-byte tails,
   non-ASCII UTF-8) against independently computed encodings.
2. **Full-pipeline (compiler integration contract):** extend the
   harness-bridge replays to the 6b parity cases: recording inputs
   computed by the NEW selection from each case's options, printed
   through the real plan → transform → print pipeline, byte-comparing
   the map (external) or payload (inline) and the reconstructed URL
   comment against the frozen writes. `inline_sources` cases prove the
   registration-point feed through `Printer::print` itself.

No hand-authored expected bytes anywhere; structural counts are asserted
from the artifact (34 cases; the suite derives its replay set by lane
filters, never by hardcoded lists that can silently narrow).
