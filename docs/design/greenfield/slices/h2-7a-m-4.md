## 5. Design details (self-contained)

### 5.1 Module layout

`crates/emitter/src/declarations/{mod.rs, state.rs, tracker.rs,
diagnostics.rs, root.rs, statements.rs, subtree.rs, ensure.rs,
selection.rs, orchestration.rs}` — the split follows the owner's own
semantic clusters (the parent §3 row-98 content list: visibility-driven
statement rewriting, member/type-level rewriting, type-annotation
synthesis via the resolver, alias/export graph, late-bound names,
accessor/overload shaping, JS-source synthesis, the diagnostics channel),
not its function boundaries. Every ported behavior carries a
`tsc-port:`/`tsc-hash:`/`tsc-span:` header at the Rust item that owns it
(ledger rule; disposition markers at authoring time — the B-1/m-3/m-3.5
lessons; `cargo xtask ledger check` in the edit loop). `lib.rs` re-exports
only what the harness needs (`DeclarationTransformer`,
`DeclarationPathResolver`, `DeclarationTransformOutcome`, the harness
bridge). Test bodies live in `crates/emitter/tests/unit/declarations/
tests.rs` (`#[path]` idiom — the walk refuses inline `#[cfg(test)]` mod
bodies in src/).
